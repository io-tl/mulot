### Summary

This was a **SQL injection with filter bypass** challenge on a PHP/MySQL application. The `?id=` parameter on the members page was vulnerable to SQLi, but a WAF blocked several attack patterns.

### Filter Analysis

The filter blocked:
- **Space character** (`%20`)
- **Comma** (`,`)
- **SQL keywords**: `AND`, `OR`, `WHERE`, `group_concat`, `concat`
- **Comparison operators**: `=`, `<`, `>`

### Bypass Technique

1. **Space** → replaced with **TAB** (`%09`)
2. **Comma** → replaced with **JOIN-derived tables** (comma-less UNION)
3. Used `LIMIT`/`OFFSET` to iterate rows (avoiding `group_concat`)


### Remediation (PHP)
Use **PDO prepared statements** with parameterized queries (`prepare()` + `bindValue()`); never concatenate user input into SQL. A WAF/regex filter is not a substitute for parameterization.
