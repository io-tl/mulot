## Challenge Solved: SQL Injection - Time-Based (Root-Me ch40)

### Flag: `????????????`

### Summary

The challenge "SQL injection - Time-Based" required exploiting a **blind time-based SQL injection** on the `member` parameter of the member profile page (`?action=member&member=1`).

### Vulnerability Details

- **Type**: Blind Time-Based SQL Injection (CWE-89)
- **Parameter**: `member` (GET, numeric context — no quotes needed)
- **Database**: PostgreSQL (confirmed via `pg_sleep()` and `generate_series()`)
- **Proof payload**: `?action=member&member=1 AND (SELECT CASE WHEN (1=1) THEN pg_sleep(2) ELSE pg_sleep(0) END) IS NULL` → response delayed ~2 seconds; when condition is `1=0` → immediate response (~15ms)

### Exploitation

Using the `CASE WHEN ... THEN pg_sleep() ELSE pg_sleep(0) END IS NULL` conditional technique:

1. **Confirmed 3 users** in the `users` table
2. **Confirmed columns**: `id`, `username`, `password`, `email`, `user`
3. **Extracted username** for `id=1`: `admin` (5 chars)
4. **Extracted password** for `id=1` (13 chars, via binary search on `ascii(substring(...))`): `????????????`
5. **Verified** by logging in via the browser as `admin` / `????????????` — successful login confirmed

### Remediation (PHP)

The `member` parameter is concatenated directly into the SQL query. Use **prepared statements with parameterized queries**:

```php
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$_GET['member']]);
```

Never concatenate user input into SQL strings — use bound parameters for all user-supplied values.
